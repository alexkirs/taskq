# Shared TaskQ blocks

Accepted under [Product](../../taskq.md#product). A compact consumer is a child of TaskQ's design and components, not an independent interpretation. Apply [shared fidelity F1–F6](https://github.com/taskqorg/specq/blob/main/design/implementation-fidelity.md); this page owns TaskQ's consumer contract.

## B1 Authority and inheritance

The [package index](README.md) and [implementation brief](implementation-brief.md) select the current reference and its editable sources. At adoption, record the TaskQ commit, source paths, asset/component version and hashes. Do not start from an older chat mock, historical menu or whichever implementation happens to be installed.

| Child block | Parent authority | Preserved interface |
|---|---|---|
| Project summary and counters | [Menu M2/M3](menu.md), [K-A1–K-A8](task-counters.md) | Project identity, provider Board link, compact state capsules, order, filtering, unknown/partial states |
| Task row and answer | Menu M3, [answer card](answer-card.md), [decisions Q1](plans-and-decisions.md) | Flowing linked identity/title, host/runtime marks, separate session links, exact source choices, draft and receipts |
| Node summary and Work mode | Menu M12, [MP2/MP10](menu-product.md), [shared resources](shared-resource-controls.md) | Target selection, current policy/usage, Mixed, capability-aware fields, review and effective readback |
| All blocks | [Visual system](visual-style.md), [final review](menu-final-review.md), [rendering](rendering-contract.md) | Tokens, typography, icon assets/meaning, internal spacing/order, focus and accessible targets |

The root contract and accepted decisions outrank illustrative fixtures. A reference shortcut cannot remove a required feature. When a parent changes, review affected consumers and their fixtures in the same delivery; do not silently freeze a divergent child.

## B2 Compact variants

TaskQ owns the compact variant alongside the parent and exercises it in native and browser fixtures. Consumers may set available width, arrange blocks, preselect an explicitly identified target and open a disclosure/detail route. They may not restyle component internals, substitute icons, reword source choices, change state symbols/order or build a second editor.

Reuse the same implementation and locally served versioned assets under the [answer-card delivery contract](answer-card.md#ownership-and-delivery). Do not add a framework or registry. Missing reusable code is an extraction task in TaskQ, not permission for a DashQ copy. Pin the design-source revision as well as the built asset version; a checksum proves provenance, not design fidelity.

Project/task extraction and adapter API: [shared project blocks](project-blocks.md). Its manifest and common fixtures accompany release staging; published-asset and native qualification remain separate gates.

A compact summary may defer detail to the same full component. Record that route and what is deferred; preserve every applicable target, state and action. The native Workspace review placement remains unchanged. DashQ may host that shared content in its own detail region, with enough width for the complete editor and one editing instance per target. Never compress Work mode into an unrelated mode/number form.

## B3 Consumer conformance

- Use the parent's provider Board/issue assets. `panels-top-left` retains its detach meaning; an icon chosen for an earlier dashboard mock is not a new TaskQ definition.
- Reuse K counters: Doing and Review remain distinct, zero capsules disappear, unknown remains explicit, Later and quiet Closed remain available, and counter targets stay separate from project navigation. No independently authored Work/Ask/Failed/Ready strip.
- Use the canonical palette, subtle capsule fills, type and geometry. Do not copy approximate colors or space counters across empty width. Aggregate and project counter strips inherit K-A8 right alignment, including wrapped lines. Large type wraps without losing identity or actions.
- Preserve Work mode's explicit target selection and full review; missing grant or capability has a reason. A summary's used/limit is not a new admission model. Current policies and untouched fields survive opening and cancellation.
- One answer editor per board/task/revision; Attention and Boards reach that instance. Refresh preserves draft/focus and never substitutes a new question silently.

Accepted extension: [finding tasks F1–F4](finding-tasks.md) owns the shared task composer, project choice and create/readback path. Consumers reuse these primitives; a new DashQ-only editor is not permitted.

## B4 Acceptance

The consumer handoff includes a parent-to-child map: source revision, component/variant, permitted placement differences, deferred routes and evidence. Reuse the existing [UI ledger](ui-acceptance.md), not a second state specification.

Compare parent and child on identical fixtures at actual size: both themes, 16/20 px, 320/360 px, long titles and counts 0/1/12/100. Check exact icons/tokens, counter order and targets, answer states, Mixed/unknown policies, review/cancel, and refresh with a focused draft. Record defects against the owning parent requirement. Fix shared causes upstream and recheck both consumers. Asset publication, native qualification and real remote actions remain separate gates.
