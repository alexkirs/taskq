# Доска taskq

Статус: утверждённый целевой дизайн GitHub/GitLab. Реализация — отдельная задача.
[Контракт](../../taskq.md#product) · [Принципы интерфейса](operator-ui.md).
Этот документ расширяется по мере проектирования доски; сейчас охватывает лейблы.

## B1 Смысл и имена

Коротко, однозначно, без криптографических сокращений. Lowercase; составные слова через `-`; без emoji.
Префикс нужен для различения группы, не ради симметрии. `p0/p1/p2` — узнаваемое исключение.

| Группа | Целевые имена | Назначение |
|---|---|---|
| Принадлежность | `taskq` | Включить issue в систему |
| Состояние | `q-ready`, `q-blocked`, `q-doing`, `q-review`, `q-ask`, `q-later`, `q-failed` | Проекция журнала; ровно одно у открытой задачи |
| Приоритет | `p0`, `p1`, `p2` | меньше — выше; отсутствие = 2; `p0` — срочная задача: проходит любой focus на любом хосте (taskq.md § 4, #790) |
| Результат | `code`, `docs`, `research`, `asset` | Один тип; префикс `type-` не нужен |
| Runtime | `run-codex`, `run-claude` | Не более одного ограничения; отсутствие = любой разрешённый |
| Хост | `host-<name>` | Не более одного ограничения; отсутствие = любой подходящий |
| Возможности | `needs-<capability>` | Все указанные требования обязательны |
| Область | `area-<name>` | Подсистема, фильтры; несколько допустимы |
| Назначение | `assignee-only` | Аккаунт подключения сервиса должен быть среди assignees |
| Служебное | `taskq-host` | Heartbeat хоста; не рабочая задача |

- `q-blocked`: незакрытая зависимость. Ответ человека — `q-ask`; нехватка мощности не меняет ready.
- `q-review`: проверка, не успех. `q-failed`: состояние задачи, не ошибка сервиса.
- Закрытие показывает платформа; `q-done` не добавлять, `q-*` с закрытой задачи снимать.
- `assigned` неточно; `only-mine` двусмысленно. Сохранить `assignee-only`.
- Не добавлять метки ради значения по умолчанию. `run-any` не выпускать как новый стандартный лейбл.
- Каждая управляемая метка имеет короткое описание: смысл, влияние на запуск, способ изменения.
- Статус меняется командой/журналом, не ручной перестановкой `q-*`; R1/R4 сохраняются.

## B2 Палитра «Только внимание»

Цвет отвечает: что выполняется, где нужен ответ, что не удалось, что срочно. Остальное нейтрально.
HEX — исходный цвет лейбла в API обеих платформ; не требование одинаковой отрисовки.

| Лейбл | HEX | Смысл цвета |
|---|---|---|
| `q-doing` | `368477` | Приглушённый зелёный: работа |
| `q-ask` | `D99536` | Янтарный: нужен ответ |
| `q-failed` | `C65365` | Мягкий красный: неудача |
| `p0` | `D1495B` | Красный: срочная задача |
| `q-ready` | `B7BEC7` | Нейтральный |
| `q-blocked` | `AEB5BF` | Нейтральный |
| `q-review` | `8C99A5` | Нейтральный |
| `q-later` | `D5D9DE` | Нейтральный |
| `taskq`, `taskq-host`, типы, `area-*`, `p1/p2` | `D5D9DE` | Второстепенные сведения |
| `run-*`, `host-*`, `needs-*`, `assignee-only` | `BAC7D3` | Нейтральный серо-голубой: ограничения |

- `taskq` не зелёный: принадлежность не конкурирует со статусом.
- Приоритет читается по имени; `p0` — единственный красный приоритет; `p1/p2` и сам факт bug не красные.
- Не различать статусы только цветом: имена всегда видны.
- Скриншоты: GitLab light использует плотную заливку; GitHub dark — оттенок текста, обводку и слабый фон.
- Контраст/читаемость проверить в обеих темах обеих платформ. CSS макета не копировать как алгоритм платформы.
- Палитра доски не меняет утверждённые цвета меню автоматически; общая семантика work/ask/failed сохраняется.

## B3 Внедрение по умолчанию

- Единый каталог имён, описаний и цветов для GitHub/GitLab. Setup и создание задач используют его.
- Новая подключаемая доска получает схему без ручной покраски каждого лейбла; внешние эффекты setup — по §6.
- Повторное применение идемпотентно; readback подтверждает имена, описания, цвета и назначения.
- Не создавать все возможные `area/host/needs` заранее; оформлять используемые значения.
- Чужие метки/описания/назначения не стирать; неизвестные метки не считать мусором.
- Ошибка прав/API не означает успех. Показать точную причину и недовыполненные изменения.

## B4 Переход существующих досок

- `priority-1` → `p1`; `priority-2` → `p2`; `q-waiting` → `q-blocked`.
- Это смена имён лейблов, не семантики состояния `waiting`, зависимостей или журнала.
- Сначала инвентаризация: используемые метки, фильтры focus/status/PM, версии сервисов и конфликты имён.
- Внедрять вместе с поддержкой чтения/записи в коде. Старый сервис не должен отменять переименование или менять допуск задач.
- Соблюдать совместимость и cutover §8/§9. Противоречие контракту — ask с конкретным планом, не скрытый обход.
- Переименование общих меток может затронуть закрытые issues. Сначала оценить эффект; §9 запрещает менять закрытые задачи. При конфликте предложить безопасный вариант или запросить изменение правила.
- Не сливать `documentation/docs`, не удалять `problem`, `taskq-events`, `codex-full-access`, `run-any`, экспериментальные/старые `host-*` без разбора использования.
- `bug/enhancement` объясняют причину работы, `code/docs` — результат; это не автоматические дубли.
- Не обходить произвольные проекты. Внедрение в текущем проекте; другие доски — только по явному списку владельца.

## Приёмка

| ID | Доказательство |
|---|---|
| B-A1 | Имена, описания и значения по умолчанию соответствуют B1; конфликтующие одиночные ограничения диагностируются. |
| B-A2 | В GitHub/GitLab readback подтверждает HEX B2; обе темы читаемы, внимание не перетягивает taskq. |
| B-A3 | Новая доска получает схему штатным setup; повтор ничего не дублирует, пользовательские метки сохранены. |
| B-A4 | CLI, сервис, проекция, приоритет и фильтры используют согласованную схему; журнал/допуск не меняют смысл. |
| B-A5 | Существующая доска переходит по явному плану; нет потерянных назначений/фильтров, гонки старых сервисов и изменений закрытых задач. |
| B-A6 | Отказ прав, частичный сбой и повтор безопасны; успех только после readback. |
| B-A7 | Проверки проекта и направленные тесты адаптеров пройдены; нативный осмотр отделён от mocks. |
