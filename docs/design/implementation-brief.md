# Бриф: реализовать меню оператора taskq

## Результат

Нативное меню macOS/Windows по утверждённой [спеке](menu.md) и [дизайн-материалам](README.md).
Плотный инструмент оператора: крупно, ясно, минимум лишней площади. Дизайн заново не изобретать.

## Сначала — исследование и обсуждение

1. Прочитать `AGENTS.md`, [taskq.md](../../taskq.md), [принципы](operator-ui.md), [меню](menu.md), оба HTML-макета, [проверки](verification.md).
2. Проверить актуальный код: `src/tray.rs`, service/status/focus/list/update в `src/main.rs`, запись `status.json`, запуск агентов и OS-unit.
3. Составить матрицу: требование M/D → есть / частично / нет → нужный контракт/данные → проверка. Отдельно сохранить весь набор M9.
4. Предложить минимальные этапы и варианты спорных решений: рекомендация, цена, ограничения, влияние на UX.
5. Обсудить с пользователем и согласовать технический план **до реализации**. Утверждённый дизайн повторно согласовывать не нужно; платформенные отклонения — нужно.

Первый результат агента — матрица пробелов и конкретный план для обсуждения, не сразу код меню.

## Что проверить и согласовать

| Область | Решение |
|---|---|
| Scope | Раздельные ARM-исполнение и PM-наблюдение; подтверждённые проекты/фильтры, версии, оригинал просьбы и readback факта |
| Агрегация | Данные досок через сервис, дедупликация, свежесть/неполнота; UI без токенов и прямого доступа к доске |
| История | Источник закрытий/failed, ID событий, интервалы/зона, восстановление; текущий failed отдельно |
| AI | Транспорт меню↔сервис, контракт ответа, проверяемые операции, подтверждение, stale/retry, восстановление запроса |
| Хранение | Настройки/черновик/история запроса и незавершённая работа без второй очереди или локальной истины, конфликтующей с R1 |
| Приём | Сохранение прежнего focus; потеря focus требует уточнения, не автоматического `all` |
| Обслуживание | Граница host/project, несколько OS-unit, общие install-ресурсы, сохранность попыток/соседних проектов |
| Платформы | Native menu/popover, ввод AI, шрифты/доступность; Windows tray не считать произвольно широким контейнером |

Исходные наблюдения, перепроверить: текущий tray работает per-project из `status.json`; есть реестр проектов и focus/status-фильтры. Нет всего требуемого агрегированного scope/readback, полной истории и AI-потока меню. M8 — список пробелов, не гарантия состояния кода.

## После согласования

- Правки решений — сначала контракт R13 и затронутая спека; затем реализация и тесты.
- Этап 1: данные/scope/readback и модель состояний; определить транспорт и владение ресурсами.
- Этап 2: сквозной срез сервис → значок → проекты/задачи → прямые ссылки; свежесть, ошибки, настройки вида/шрифта.
- Этап 3: pause/resume, cadence, обслуживание M9; подтвердить изоляцию проектов.
- Этап 4: AI-ввод, история, уточнение/подтверждение, применение/readback, восстановление.
- Порядок уточнить по зависимостям; этап не означает разрешение молча вычеркнуть остальные функции.

## Визуальный источник

- Структура меню — `menu-prototype.html`; финальные значки — **`icon-studies.html`**. Старые значки из меню не переносить.
- Сводка: «Единая полоса», крупные цифры над пропорциональными составными барами; active без q/▶.
- Общая пауза: те же данные/геометрия в сером; компактная q с Ⅱ строго по центру. Не отдельная кнопка паузы.
- Размеры — ориентиры. Проверить реальные OS-ограничения, многозначные числа, темы и масштаб; отклонения обсудить.
- Тестовые данные макетов не считать состоянием реальных issues. Production-assets и нативный renderer предстоит сделать.

## Приёмка и передача

- Покрыть D-A1–D-A8 и M-A1–M-A13; доказательство и оставшиеся ограничения записать в `verification.md`.
- Проверки макетов: `node docs/design/menu-prototype.test.cjs`, `node docs/design/icon-studies.test.cjs`.
- Проверки проекта: `cargo test --locked`, `cargo run -- selftest`; соблюдать репозиторный launcher и §7.
- Lifecycle-изменения: таблица → golden traces → fold → adapters по executable behavioral model.
- Нативно проверить обе ОС: 1:1, темы, масштаб, длинные названия, крупный шрифт, клавиатуру/скринридер, pause/mixed/stale, несколько проектов, отказ AI и повтор подтверждения.
- Показать пользователю реальные экраны и сквозные действия. Отдельно отметить mocks, непроверенные платформы и недостающие функции; не объявлять их готовыми.

Этот бриф не разрешает менять model/permissions, развёртывать сервис или публиковать релиз. R1/R9/R10/R11/R12/R13 сохраняются.
